# Security Policy

## Supported versions

Security fixes target the latest published release. A fix may land on `main` before the next release. Older releases are not guaranteed to receive security updates unless maintainers announce otherwise.

## Reporting a vulnerability

Please do not open a public issue containing vulnerability details, credentials, proof-of-concept payloads, or affected user data.

Use GitHub's private vulnerability reporting form from the repository's **Security** tab. If private reporting is unavailable, contact a maintainer through an established private channel and ask where to send the report without including sensitive details in the initial message.

Include, when available:

- the affected version or commit;
- the affected component and configuration;
- reproduction steps with the minimum data required;
- the expected and observed security impact;
- any suggested mitigation.

Maintainers will acknowledge the report, validate its impact, coordinate a fix and release, and credit the reporter if requested. Disclosure timing should be coordinated until affected users have a reasonable opportunity to update.
